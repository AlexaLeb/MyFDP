## 1. Источник и состав данных

**Источник:** M5 Forecasting Accuracy — публичный бенчмарк Kaggle на основе реальных данных о продажах сети Walmart. Используется как прокси-датасет для разработки методологии квантильного прогнозирования спроса.

**Файлы:**

| Файл | Размер | Содержание |
|---|---|---|
| `sales_train_evaluation.csv` | 30 490 × 1 947 | Дневные продажи по SKU, d_1–d_1941 |
| `calendar.csv` | 1 969 × 14 | Даты, дни недели, праздники, SNAP-флаги |
| `sell_prices.csv` | ~6.8 млн × 4 | Цены по неделям на уровне item × store |
| `sample_submission.csv` | 60 980 × 29 | Формат прогноза (F1–F28) |

**Структура:** одна строка = один SKU (item × store), колонки d_1…d_1941 — дневные продажи.

**Иерархия данных:**
- 3 штата → 10 магазинов → 3 категории → 7 департаментов → 3 049 товаров × 10 магазинов = **30 490 рядов**
- Временной горизонт: **1 941 день (январь 2011 — июнь 2016)**

## 2. Базовый EDA с выводами, важными для моделирования

### Разреженность и intermittent demand
- **68% всей матрицы продаж — нули.** Медианный SKU не продаётся 73% дней
- **16.8% SKU (5 133)** имеют >90% нулевых дней — ultra-sparse, требуют отдельной стратегии
- По категориям разреженность принципиально разная:

| Категория | Доля нулей | Ultra-sparse SKU | Среднее продаж/день |
|---|---|---|---|
| HOBBIES | 77.1% | 29.5% | 0.57 |
| HOUSEHOLD | 71.6% | 19.8% | 0.73 |
| FOODS | 61.8% | 9.7% | 1.65 |

### Распределение спроса
- Сильно правосторонний хвост: медиана ~1–2 шт/день, max = 763, p95 = 11
- Для моделирования: log-трансформация таргета улучшит обучение; квантиль 0.5 у большинства SKU = 0

### Сезонность (статистически подтверждена)
- **Недельная** — Kruskal-Wallis H=754, p<0.001. Вс/Пн — пик, Ср–Пт — минимум. `wday` — обязательный признак
- **Годовая** — H=22.9, p=0.018. Слабее, но значима
- **ACF/PACF** подтвердили лаги 7, 14, 28 для всех трёх категорий. FOODS также показывает долгую память (лаг 56+)

### Рекомендуемые лаги для feature engineering
`[1, 2, 7, 14, 28, 56]` + скользящие средние на окнах 7/28/56 дней

### Праздники и SNAP
- Глобальный эффект праздников: +0.4%, p=0.37 — незначим. Но локально: LaborDay +21.8%, SuperBowl +18.2%, Easter +14.2%
- SNAP-эффект значим (+11.5%, p<0.001) и **неоднороден по штатам**: CA +7.3%, TX +11.9%, WI +24.0% — использовать три отдельных признака, не агрегировать

### Цены
- Общий рост: +10% за 5 лет. 95% SKU имеют CV < 0.1 — цены стабильны
- 11.1% SKU меняли цену более чем на 50% — промо или переоценки
- Прямая корреляция цена–продажи слабая (медиана = -0.052). Полезнее: `price / rolling_mean_price_28d` как признак промо

### Активность SKU
- 48.2% SKU активны на всём горизонте, 44% появились после первого года
- **Поздние SKU систематически разреженнее** (83.1% нулей vs 62.3% у ранних), но медиана ненулевых продаж одинакова (2.0) — паттерн спроса не отличается, только длина истории
- `age_of_series` (дней с первой продажи) объясняет большую часть разницы между группами

## 3. Оценка качества разметки

M5 — это реальные транзакционные данные Walmart, не ручная разметка. "Качество разметки" здесь означает корректность временных рядов и наличие аномалий.

**Проверено:**
- Отрицательных значений продаж нет
- Дубликатов ключей item × store × day нет
- Все `d` из sales присутствуют в calendar
- Пропусков в sell_prices 5.3 млн (16%) — товары без цены в начале жизни, заполнены ffill/bfill внутри SKU

**Выбросы (IQR-метод, Q3 + 3×IQR):**
- Применялся только к активным SKU (mean > 1) — 8 117 SKU (26.6%)
- На разреженных рядах IQR=0, метод некорректен
- Среди активных SKU: 0.997% значений — выбросы
- Экстремальные случаи: значения 600–750 при средних ~130

**Предложения по улучшению:**
- Winsorizing на уровне Q3 + 3×IQR для активных SKU
- Добавить бинарный признак `is_outlier_day` — модель сама взвесит аномалии
- Для sparse SKU (IQR=0): применять rolling mean + N×std или исключать из основного обучения

**Ограничения датасета (M5 → РФ e-commerce):**

| Характеристика | M5 (Walmart, США) | Целевой домен (РФ e-commerce) |
|---|---|---|
| Тип канала | Офлайн супермаркет | Онлайн магазин |
| Сезонность | Американские праздники | Российский календарь |
| SNAP-эффект | Есть, значим (+11.5%) | Аналога нет |
| Горизонт данных | 5.5 лет | Обычно < 1–2 лет |

M5 используется как прокси-датасет для разработки методологии. Обобщаемость на РФ e-commerce проверяется эмпирически на этапе Evaluation.

## 4. Алгоритм формирования выборки и стратегия валидации

### Алгоритм формирования датасета

1. **База:** `sales_train_evaluation.csv` — wide → long через `melt` (одна строка = один SKU × один день)
2. **Merge с calendar** по ключу `d` → дата, wday, month, события, SNAP-флаги
3. **Merge с sell_prices** по `[store_id, item_id, wm_yr_wk]` → цена
4. **Маска активности:** исключить дни до первой продажи SKU — убирает предисторические нули и устраняет систематический bias
5. **Обработка выбросов:** winsorizing для активных SKU (mean > 1), флаг `is_outlier_day`
6. **Feature engineering:** лаги, rolling-признаки, ценовые признаки

### Отбор данных

**Ultra-sparse SKU (>90% нулей, 16.8%):**
- Первый этап: исключить из основного обучения, зафиксировать как ограничение
- Второй этап: Croston / two-stage подход (отдельная модель P(sale>0) + объём)

**Временной горизонт:**
- Обучать на полном горизонте d_1–d_1885, добавить `age_of_series` как признак
- На этапе моделирования: эксперимент — сравнить качество модели на последних 2 vs 5 годах

### Стратегия валидации

**Temporal split** — random split недопустим (data leakage):

```
Train:  d_1    — d_1885  (1 885 дней) — обучение
Val 1:  d_1886 — d_1913  (28 дней)    — разработка, подбор гиперпараметров
Val 2:  d_1914 — d_1941  (28 дней)    — финальная оценка (нетронутый holdout)
```

**Walk-forward validation** (на этапе моделирования):
```
Fold 1: train d_1–d_1773 → predict d_1774–d_1801
Fold 2: train d_1–d_1801 → predict d_1802–d_1829
Fold 3: train d_1–d_1829 → predict d_1830–d_1857
Fold 4: train d_1–d_1857 → predict d_1858–d_1885
```

**Почему горизонт 28 дней:**
- Соответствует структуре соревнования M5
- Покрывает ровно 4 недели — полный цикл недельной сезонности
- Кратен 7 → нет смещения по дням недели между train и val
- Соответствует типичному горизонту пополнения склада в e-commerce

**Метрики:** Pinball Loss для квантилей 0.1 / 0.5 / 0.9, WRMSSE как референс M5
